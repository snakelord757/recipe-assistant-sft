# Локальный помощник по рецептам: SFT Qwen3-0.6B

В репозитории опубликованы код, синтетические датасеты, исходные ответы моделей,
метрики, графики loss и отчёты. **Веса базовой модели и LoRA-адаптеров не включены**;
окружения Python, CUDA-wheel и кэши также исключены из Git.

Результаты: [V1](results/report.md), [V2](runs/v2/report.md),
[125 сравнений V1/V2](runs/v2/comparisons.html), [датасет V2](data_v2/README.md).
HTML со сравнениями нужно скачать/клонировать и открыть в браузере; на GitHub
он показывается как исходный код. Оценки сделаны ассистентом на синтетических
тестах, а не независимой экспертной группой.

## Запуск из чистого клона

Проверенное окружение: Windows x64, Python 3.12, NVIDIA RTX 5060 Ti 16 GB,
совместимый драйвер CUDA 12.8. Python 3.12 должен быть установлен заранее.
В PowerShell из корня клона:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install "https://download.pytorch.org/whl/cu128/torch-2.7.1%2Bcu128-cp312-cp312-win_amd64.whl"
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe download_model.py

# Восстановить адаптер V1: веса намеренно не опубликованы
.\run_experiment.ps1
# Обучить V2 и сравнить с восстановленной V1
.\run_v2.ps1
```

Нужен интернет для установки пакетов и загрузки базовой модели. После загрузки
запуски работают локально, без платного API. Скрипты перезаписывают результаты
соответствующей версии: сохраните копию, если хотите оставить опубликованный
эксперимент без изменений. Точные версии пакетов — в
[environment_packages.txt](results/environment_packages.txt).

Датасеты уже включены. Если требуется пересобрать их, выполните сначала
`build_dataset.py`, затем `build_dataset_v2.py`. `.gitattributes` сохраняет
байты JSONL без изменения переводов строк для совпадения опубликованных SHA-256.

Скрипты `review_results.py` и `review_v2.py` содержат ручную оценку **сохранённых**
ответов. После нового обучения нужно проверить новые ответы и обновить оценки;
перенос старых меток на другие ответы недопустим. Затем `make_report.py` и
`report_v2.py` собирают отчёты. Базовая модель Qwen3-0.6B загружается из
[официального репозитория](https://huggingface.co/Qwen/Qwen3-0.6B) с закреплённой
ревизией; её лицензия Apache-2.0 доступна там же.

## Расширенный эксперимент V2

Данные V2: `data_v2/README.md`, 4360 правильных ответов на 200 вариантах рецептов.
Полный запуск: `.\run_v2.ps1`. Видимый UTF-8 просмотр лога: `.\show_progress_v2.ps1`.
Физический batch2, accumulation8, эффективный batch16, до трёх эпох.
Первый запуск batch4 остановлен из-за заполнения GPU-памяти, его веса не используются.
Выбирается лучший адаптер по validation loss.

Новая модель: `.\.venv\Scripts\python.exe chat.py --recipe recipe_example.txt --adapter runs/v2/adapter`.
Артефакты V2 находятся в `runs/v2/`, исходные результаты и адаптер V1 сохранены.
Новый тест (80 вопросов) оценивается на обеих версиях, старый тест (45) служит
проверкой регрессий. Новый набор отделён по семействам рецептов.

Итоговый отчёт после оценки: `runs/v2/report.md`; все сравнения:
`runs/v2/comparisons.html`. Скрипт `report_v2.py` строит их из измерений и ручных
оценок в `runs/v2/reviews.json`, не является автоматическим семантическим судьёй.

Проект обучает небольшую модель на правильных ответах ассистента и сравнивает
ответы до и после обучения с эталонами на отдельной тестовой выборке.

## Данные

См. `data/README.md`. 400 пар предпочтений (100 на задачу) представлены также
как 800 размеченных ответов. В SFT используются только 400 правильных ответов.
Отложены 25 валидационных и 45 тестовых вопросов на других рецептах.
Перегенерация: `.\.venv\Scripts\python.exe build_dataset.py`.

## Запуск

Подготовленное окружение: Windows, Python 3.12, PyTorch CUDA 12.8, NVIDIA GPU.
Все команды выполняются из корня проекта.

```powershell
# Полный эксперимент: исходная модель, обучение, обученная модель
.\run_experiment.ps1

# Этапы можно запускать отдельно
.\.venv\Scripts\python.exe experiment.py before
.\.venv\Scripts\python.exe experiment.py train --epochs 8
.\.venv\Scripts\python.exe experiment.py after

# Вопросы к собственному рецепту в UTF-8 файле
.\.venv\Scripts\python.exe chat.py --recipe recipe_example.txt
# Сравнить с исходной моделью: добавить --base
```

Повторный полный запуск перезаписывает результаты и адаптер. При необходимости
сначала скопируйте папки `results` и `adapter` для сохранения предыдущего эксперимента.
Прогресс и loss показываются в консоли; полный лог — `results/console.log`.

Для нового окружения установите зависимости `requirements.txt` и CUDA-сборку
PyTorch, подходящую видеокарте. В данном эксперименте выбран официальный wheel:

```text
https://download.pytorch.org/whl/cu128/torch-2.7.1%2Bcu128-cp312-cp312-win_amd64.whl
```

`download_model.py` загружает веса непосредственно с Hugging Face в
`models/qwen-local`. `download_cuda.py` — резервный загрузчик официального wheel
частями для нестабильной сети. Веса и зависимости не включаются в Git.
Карточка модели: https://huggingface.co/Qwen/Qwen3-0.6B (Apache-2.0).

## Методика

LoRA rank 16, alpha 32, dropout 0.05, восемь эпох, LR 0.0002, batch 4,
накопление градиента 4. Маскируются токены запроса: loss вычисляется только
на целевом ответе. Лучший адаптер выбирается по validation loss.
Тест не используется для выбора эпох или параметров.

Все вопросы задаются независимо. При тесте: BF16, без thinking, greedy,
batch size 1, max_new_tokens 160. До замера скорости модель прогревается.
После обучения адаптер сливается с базовыми весами в памяти для сравнения скорости.
Тестовый набор невелик и синтетический: выводы относятся к данному эксперименту.

## Результаты

- `results/report.md`: итоговый отчёт после завершения эксперимента и оценки.
- `results/comparisons.html`: все ответы учителя и модели до/после.
- `results/loss.png`: график обучения.
- `results/before.json`, `results/after.json`: исходные ответы и тайминги.
- `results/review.json`: проверка каждого ответа ассистентом с объяснениями.
- `results/evaluation_protocol.md`: заранее зафиксированные критерии.
- `adapter/`: сохранённый лучший адаптер и токенизатор.

`make_report.py` пересобирает отчёт из измерений и уже заполненного review.json;
сам скрипт не является автоматическим семантическим судьёй.
Учитель — ассистент чата; его отдельная скорость и стоимость API не измеряются.
