# Датасет кулинарного помощника

## Нужно ли 100 неправильных ответов на задачу?

Нет. Это выбранный объём набора, а не установленный порог качества.
Для SFT используются только правильные ответы, включая правильные отказы на
посторонние вопросы. Нельзя подать неправильный ответ как обычный целевой ответ
SFT: это будет обучать воспроизводить ошибку. Сам по себе флаг `is_correct=false`
не меняет функцию потерь.

Для DPO нужны пары предпочтений `chosen` / `rejected`. Наличие 100 таких пар
не гарантирует улучшение. Для проверки пользы негативов необходимо сравнение
SFT и SFT+DPO при одинаковой исходной модели и на общей отложенной выборке.
Подбирать настройки следует по валидации, а не по итоговому тесту.

Рекомендуемый первый этап: SFT на `sft_train.jsonl`. Отрицательные ответы
сохранены отдельно для анализа ошибок и возможного второго этапа DPO.

Источники: [форматы TRL](https://github.com/huggingface/trl/blob/main/docs/source/dataset_formats.md),
[DPO Trainer](https://huggingface.co/docs/trl/en/dpo_trainer),
[исходная статья DPO](https://arxiv.org/abs/2305.18290).

## Объём

| Задача | Правильные ответы | Неправильные ответы | Файл |
|---|---:|---:|---|
| Удержание рецепта: шаги, состав, отсутствие сведений | 100 | 100 | attention_200.jsonl |
| Отказ на запросы вне кулинарии | 100 | 100 | refusal_200.jsonl |
| Замена ингредиентов | 100 | 100 | substitution_200.jsonl |
| Пересчёт порций | 100 | 100 | scaling_200.jsonl |
| Всего | 400 | 400 | answers_800.jsonl |

Это 400 уникальных сочетаний рецепта и вопроса. Для каждого записаны два ответа.
Число 800 обозначает размеченные ответы, не независимые вопросы.
20 рецептов обучения; по пять вопросов каждой задачи для каждого рецепта.
В отказах есть 100 разных посторонних запросов, часть — с попыткой сменить роль.
В заменах покрыты предложение альтернативы, проверка плохого совета,
двойное количество / исключение сахара, неоправданная гарантия идентичности
и запрос уточнений при недостаточных данных.

## Файлы и использование

- `train.jsonl`: 400 пар с `chosen`, `rejected`, объяснением ошибки и метаданными.
- `sft_train.jsonl`: 400 диалогов, только правильные целевые ответы.
- `answers_800.jsonl`: плоский набор с метками `is_correct`.
- `*_200.jsonl`: отдельные задачи в таком же плоском формате.
- `validation.jsonl`: 25 пар на пяти отдельных рецептах.
- `test.jsonl`: 45 пар на восьми отдельных рецептах, включая пограничные случаи.

Валидация и тест не входят в 800 обучающих записей. Рецепты между тремя
выборками не пересекаются. Шаблоны заданий частично общие: это проверка переноса
на новые рецепты, а не полностью новые виды задач. Тестовые дополнительные
сценарии включают ноль порций, неуказанное число порций, отсутствующие сведения
и завершение рецепта. Пять вопросов на рецепт коррелируют; их нельзя считать
столь же независимыми, как вопросы на разных рецептах.

## Происхождение и ограничения

Рецепты, ответы и правила генерации составлены ассистентом в этом чате.
Учитель — ассистент, не отдельная скачанная модель и не вызов API.
Количества пересчитываются программно; формулировки и ответы синтетические.
Отрицательные примеры намеренно содержат ошибки и не являются советами.
Часть негативов очевидная и шаблонная. Для полезного DPO предпочтительно
добавить реалистичные ошибки самого ученика на новых обучающих запросах,
проверив каждый ответ и не используя итоговый тест.

Механические проверки: число записей и классов, непересечение рецептов,
уникальность сочетаний рецепта и вопроса, различие chosen и rejected.
Эти проверки не заменяют независимую экспертную оценку кулинарных советов.
Набор не покрывает весь спектр аллергий, пищевой безопасности, сложных замен
в выпечке, единиц измерения, длинных рецептов и многотуровых разговоров.
Дробное количество яйца означает пропорциональную часть взбитой яичной массы;
в бытовом приложении потребуется дополнительное объяснение и округление.

SFT-эксперимент выполнен; результаты находятся в `../results/report.md`.
Нельзя выдавать совпадение ответов ассистента со своим же эталоном
за независимые 100% качества учителя.
