# V2: протокол сравнения

Сравниваются сохранённая V1 (лучший адаптер первой эпохи) и новая V2.
V2 начинает SFT с той же исходной Qwen3-0.6B, а не продолжает адаптер V1.
Это эксперимент по расширению данных с более низкой learning rate, а не чистая
абляция одного фактора: изменились данные, LR, число эпох и число обновлений.

Данные: 4360 train / 245 validation. LoRA r16/alpha32/dropout0.05,
LR 0.00008, три эпохи максимум, seed42, batch2, accumulation8,
cosine schedule, 5% warmup. Последняя неполная группа накопления нормируется
по фактическому числу батчей. Сохранение по минимальному validation loss;
patience2. Тесты не используются для выбора чекпойнта или гиперпараметров.

Пробный запуск с batch4 остановлен в начале первой эпохи из-за заполнения
видеопамяти. Его веса не используются. Обучение перезапущено от базы с batch2,
accumulation8, тем же эффективным батчем 16. Лог пробы: pilot_batch4.log.

Общие настройки инференса: исходный системный промпт V1, BF16, no thinking,
greedy, max_new_tokens160, batch1. Адаптеры сливаются в память перед замерами.
Исправления ответов, внешний калькулятор, правила маршрутизации и постобработка
ответов в этом эксперименте не используются.

Два набора:

1. Старые 45 вопросов: регрессии после анализа ошибок V1. Сравнение с сохранёнными
   ответами V1; их оценки и критерии не меняются.
2. Новые 80 вопросов на десяти отложенных семействах. 40 задач на числа, 30 на
   замены, 10 на следующий шаг. V1 и V2 генерируют ответы на один и тот же набор.

Полный успех = решён весь вопрос без существенных фактических ошибок.
Числа проверяются по Decimal-эталонам; эквивалентные единицы разрешены. Для
округления допустима абсолютная погрешность до 0.01 г/мл и 0.0001 кг.
Для списка должны быть верны ВСЕ продукты и количества. Для единственного
ингредиента при явном запросе расчёта нужны корректная формула и итог.

Для замен допускается разумная альтернатива, не обязательно буквальный эталон,
но соблюдаются ограничения. Запрошенное количество должно быть корректным.
Неуместная добавленная инструкция делает весь ответ ошибочным, даже если
первое предложение правильно. В открытом вопросе количество приветствуется,
но его отсутствие само по себе не ошибка, если вопрос количества не требовал.
Шаги проверяются по рецепту; перефразирование и очевидные опечатки допустимы.

Проверка выполняется тем же ассистентом, который составил данные. Это не слепая
независимая оценка. Ответы и комментарии сохраняются для ручной перепроверки.
Обе выборки небольшие и синтетические, вопросы одного семейства коррелируют.

Latency и board-power измеряются тем же кодом, что V1. Энергия GPU не включает
весь ПК и амортизацию. Тариф 6 RUB/kWh — иллюстративный. Для учителя-ассистента
API latency и цена недоступны. Его ответы служат эталоном, не отдельным замером.
